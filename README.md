# 学分申请系统 · Vue 3 v1.8

基于 v1.7 完整工程更新：新增消息发送、文件管理打包下载、系统信息保存的统一模态进度反馈；优化提交状态弹窗的首屏显示速度，保留原有申请、审核、上传、初始化、关于信息与 Cloudflare/Gitee API 逻辑。

## 部署方法

将压缩包内的整个目录发布至 **Cloudflare Pages** 的项目根目录，保持 `functions/`、`assets/`、`vendor/`、各 `.html` 文件的相对路径。

- Pages 框架预设：`None`，无需前端构建；发布目录 `.`。
- 保留之前配置的 `GITHUB_TOKEN`、`GITHUB_OWNER`、`GITHUB_REPO`、`GITEE_TOKEN`、`GITEE_OWNER`、`GITEE_REPO`、`GITEE_BRANCH` 等环境变量。
- 关于设置会在 **Gitee 仓库中创建或更新 `data/about.json`**；其余 `data/settings.json` 等文件保持原样。无需手工预先创建 `data/about.json`。
- **建议：** 在 Cloudflare Pages 的 Secrets 中新增强随机字符串 `ABOUT_SESSION_SECRET`，用于签名“关于”信息的 system 写入凭证。若未设置，则使用现有 `GITEE_TOKEN` 作为签名密钥。请勿将以上秘密写进前端代码。
- **部署新版后，system 账户须退出并重新登录一次**，才能获得新的关于信息写入凭证。凭证有效期 12 小时，过期后请重新登录。普通 admin 和学生可读“关于”，但不能写入。
- 通过页面上的链接可直接访问 `/about.html`；system 管理端的 `关于` 导航指向 `/about.html?view=admin`，方便查看后返回系统管理。

## v1.8 更新内容

### 1. 管理端操作模态进度（Vue 3）

- **消息发送：** 二次确认后立即显示模态窗口，按**服务器已响应的接收人数**计算进度（已处理人数 / 总人数），显示成功/失败数量；处理中不可关闭、重复点击。消息继续采用顺序写入，避免多个 Gitee 写入同时竞争 `data/messages.json` 的 SHA。部分失败时保留失败学生的勾选，便于重试，避免重复发送成功消息。
- **文件管理 → 打包下载全部：** 按已处理文件数显示获取进度；文件读取采用**最多 5 个并发请求**，避免原来的逐个等待。待文件获取完成后，继续显示 JSZip 实际生成进度。ZIP 使用 `STORE` 模式跳过无谓的重复压缩，适合图片、PDF、Office 等已压缩文件，优先下载速度而非 ZIP 体积。生成成功后浏览器开始下载，失败文件数量会在弹窗中说明；相同文件名通过前缀保留所有上传记录。
- **系统管理 →（关于）系统信息设置：** 校验通过后立即打开不可关闭的处理模态框，等待 Gitee 写入回执；由于普通 `fetch` + Gitee 更新 API **没有真实百分比**，这里使用不定进度动画，不能误将发送成功当作持久化成功。服务器确认后提示成功，出错后展示原因并解锁表单。
- 处理中阻止重复操作，提供浏览器关闭/离开前的标准确认提示（无法绝对拦截强制关闭、后台关闭或断电）。操作成功或失败后展示结果，可以关闭弹窗。

### 2. 提交状态弹窗即时呈现

- 单击 **文件管理 → 提交状态** 后先打开弹窗，不再 `await` 学生/上传两个 API 的网络响应。
- 优先直接渲染当前页面已有的已交/未交列表；再次打开时还可读取**按管理账号隔离的 sessionStorage 列表快照**。弹窗显示快照时间和同步状态，随后在后台刷新最新数据。
- 当首次访问且尚未获取上传记录时，会立即显示加载提示，**不能在接口返回之前凭空显示未获取的名单**。
- 学生和上传记录的短时缓存、进行中请求复用、刷新并发去重，减少重复访问 Gitee；保留原每 8 秒检查和手动刷新、Excel 导出。

### 3. 测试与限制

- 无须新增环境变量；Cloudflare Pages Functions 与 v1.7 完全一致。
- 并发下载速度仍受 Gitee 和 Cloudflare 响应速度、用户带宽、文件大小及浏览器内存限制。大 ZIP 在浏览器内存中生成，建议避免一次打包极大文件集。
- 下载进度百分比以**文件完成数**计，不是字节级网络进度；打包阶段显示 JSZip 真实生成百分比。
- 本地测试使用模拟接口，不构成真实 Gitee 写入与线上速度保证。

## v1.7 更新内容

### 1. 活动申请的提交模态窗口

在 `/upload.html` 完成必填项及证明图片选择后，点击 **提交申请**：

1. Vue 3 控制的模态窗口立即打开，遮罩下的表单不可操作、提交按钮禁用，避免重复提交。
2. `XMLHttpRequest.upload` 的**实际上传字节进度**用于显示百分比与进度条（不是凭空计时的进度）。
3. 上传达到 100% 后显示 **“正在提交申请…” / “上传完成 · 等待服务器响应”**。注意上传 100% 不等于后端保存成功。
4. **收到成功响应后**，显示成功状态并进入学分总览；失败、超时或断网则显示错误说明，提供“关闭并返回表单”，按钮恢复可用。
5. 请求处理中使用浏览器 `beforeunload` 提示减少误关闭，无法绝对阻止强制关闭、断电、进程退出等场景。

### 2. 公开关于页 `/about.html`

左右侧边栏都增加 **“关于”** 入口。页面内容由新的 `GET /api/about` 读取 Gitee `data/about.json`，未创建该文件时显示默认介绍；加载失败提供重试。

展示字段：标题、副标题、系统介绍（多行纯文本）、维护单位、版本、联系邮箱、官方网站，以及更新日期。Vue 文本绑定会自动转义文字，不执行用户提供的 HTML。页面针对手机、平板、桌面适配。

### 3. system “（关于）系统信息设置”

`/admin.html?tab=about`：system 账户可编辑上述全部字段、预览公开页面并保存，提交时防重复点击，失败时显示错误信息。管理员选项卡在手机端继续使用下拉选择。

- 新接口：`GET /api/about` **公开只读**；`PUT /api/about` **只允许 system 账户**。
- 为解决原项目的可预测管理令牌不适合保护新写入接口的问题，`/api/auth` 给已验证的 system 登录额外发放 HMAC 签名的限时 `aboutToken`（前端存储键为 `aboutWriteToken`）。`PUT /api/about` 验证签名、时限、system 权限，并重新核对 GitHub 管理员列表的当前角色。
- 其他原有 API 的认证方式与业务接口没有迁移；**现有工程的旧管理员认证仍采用历史兼容机制**，建议未来整体升级正式服务端会话认证。
- Gitee 写入通过原 `functions/utils/gitee.js` 工具，支持新建（POST）与带 SHA 更新（PUT）；保留 UTF-8 中文。
